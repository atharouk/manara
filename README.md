# منارة

نسخة مطوّرة من النموذج الأولي: دخول منفصل للمعلّم والطلاب، تلاوة قرآنية صوتية، تسجيل تلاوة الطالب ومراجعة المعلّم، تصدير التقارير، حفظ تقدّم الطلاب والمهام في Supabase، ونشر ثابت على Vercel عبر GitHub.

الشعار نصّي عربي بخط «أميري/النسخ» داخل إطار هندسي ثماني ذهبي مستوحى من الزخرفة الإسلامية، مع نجمة صغيرة وكلمة «منارة»؛ يظهر في الرأس وفي شاشة الدخول.

> **الرابط المباشر:** https://manara-atharok1.vercel.app
>
> **المستودع:** https://github.com/atharouk/manara-app
>
> **حساب المعلّم التجريبي:** `manara.teacher@example.com` أو `reysahrawi2013@gmail.com` — كلمة المرور: `Manara@2026`
>
> **حسابا طلاب تجريبيان:** `ahmad.student@example.com` و`maryam.student@example.com` — كلمة المرور: `Student@2026`

## البنية

| الملف | الوظيفة |
|---|---|
| `index.html` | الواجهة (من النموذج الأصلي) + شاشة الدخول |
| `data.js` | محتوى الدروس والمصحف (مستخرج من السطر 73 الأصلي) |
| `app.js` | المنطق + طبقة Supabase |
| `config.js` | رابط المشروع والمفتاح العام `anon` |
| `supabase/schema.sql` | الجداول وسياسات الأمان والبيانات التجريبية |
| `supabase/boards.sql` | جدول لوحات السبورة وسياسات الوصول إليها |

## 1) إعداد Supabase

1. أنشئ مشروعاً جديداً في https://supabase.com/dashboard.
2. افتح **SQL Editor** وشغّل محتوى `supabase/schema.sql`، ثم `supabase/boards.sql` لإضافة لوحات السبورة السحابية.
3. من **Project Settings > API** انسخ:
   - `Project URL`
   - `anon public` key
4. ضعهما في `config.js`:
   ```js
   export const SUPABASE_URL = 'https://xxxx.supabase.co';
   export const SUPABASE_ANON_KEY = 'eyJhbGciOi...';
   ```
5. من **Authentication > Providers** تأكد أن `Email` مفعّل. أنشئ مستخدم معلّم من **Authentication > Users > Add user**، ثم شغّل `schema.sql` ليُمنح دور `teacher` تلقائياً.

> ⚠️ لا تضع `service_role` key في المتصفح أبداً. المفتاح `anon` عام بطبيعته، والحماية تتم عبر سياسات RLS في `schema.sql`.
>
> ملاحظة أمنية: **التسجيل الحر معطّل** (`disable_signup`)، وتُنشأ حسابات المعلّمين يدوياً من **Authentication > Users > Add user**. أدوار المستخدمين محفوظة في جدول `user_roles`، والوصول محكوم بسياسات RLS: المعلّم يرى كل البيانات، والطالب يرى سجله وإنجازاته ومهامه فقط.

### حسابات الطلاب (جديد)

من صفحة **الطلاب** اضغط زر **حساب** بجانب الطالب:

- **إنشاء الحساب:** أدخل بريد الطالب وكلمة مرور (6 أحرف فأكثر). تُنشأ هوية Supabase تلقائياً عبر دالة `create_student_account` دون أي مفتاح سري في المتصفح.
- **تحديث كلمة المرور** أو **إلغاء الربط** متاحان من نفس النافذة.
- الطالب يسجّل الدخول ببريده وكلمة مروره، ويظهر له شريط تنقّل مختصّ: الرئيسية، القرآن، والمواد فقط. لا يرى صفحات المعلّم، ولا يمكنه تبديل الطالب المعروض.
- سياسات RLS تمنعه من قراءة أو تعديل بيانات طالب آخر حتى لو استخدم API مباشرة.

### التلاوة الصوتية

من صفحة **القرآن**:

- اختر السورة، ثم اضغط ▶ بجانب أي آية، أو زر **تلاوة السورة** من أول آية.
- القارئون المتاحون: مشاري العفاسي، محمود خليل الحصري، محمد صديق المنشاوي.
- يمكن تغيير السرعة (0.75× ↔ 1.5×) وتفعيل **تتابع تلقائي** للانتقال للآية التالية.
- تُحمَّل التلاوة من `cdn.islamic.network` عبر أرقام الآيات العالمية، دون مفتاح API أو حساب خارجي. تحتاج التلاوة إلى اتصال بالإنترنت.
- أرقام الآيات تُحسب من طول السور في `data.js`، فتطابق ترقيم المصحف العالمي (مثلاً: البقرة ١ = 8.mp3).
- زر ▶ بجانب البسملة في السور غير المفتتحة يشغّل البسملة وحدها، بينما تلاوة السورة تبدأ بالآية الأولى كاملة.

### السبورة الذكية

من عنصر **🖊️ السبورة** في القائمة (للمعلّم وللطالب):

- عند فتح السبورة تحتل كامل الشاشة، وتظهر كل الأدوات في شريط واحد فوق اللوحة (يتفاف على الهاتف)، مع زر **🏠 رجوع** للخروج.
- الشريط يبدأ بحالة **مصغّرة** (أيقونات فقط) لتكبير مساحة الرسم، وزر **🔼 توسيع** يعرض الأسماء كاملة؛ يُحفظ إعدادك في `localStorage`.
- زر **⛶ ملء الشاشة** اختياري لإخفاء شريط المتصفح أيضاً، واللوحة تبقى ممتلئة حتى بدونه.
- أدوات الرسم: 🖊️ فرشاة، 🖍️ تلوين شفاف (هاي لايتر)، 🧽 ممحاة تحذف العناصر، 🅰️ نص عربي، وخط/سهم/مستطيل/دائرة تُرسم بالسحب.
- ثمانية ألوان وسمك قابل للتعديل (٢–٢٨) ينطبق على الفرشاة والأشكال، ويضبط أيضاً حجم النص.
- النص يُضاف بالنقر على مكانه ثم الكتابة في المربع الظاهر وEnter أو «إضافة».
- تراجع/إعادة بالأزرار أو `Ctrl+Z` / `Ctrl+Y`، ومسح كامل للوحة، وخلفية شبكية اختيارية.
- تنزيل اللوحة كصورة PNG.
- تُحفظ اللوحة تلقائياً في Supabase في جدول `public.boards` (معرّف `teacher` للمعلّم، ومعرّف الطالب لكل طالب)، مع نسخة احتياطية في `localStorage` عند انقطاع الاتصال. تظهر حالة الحفظ أسفل اللوحة.
- سياسات RLS: المعلّم يرى كل اللوحات لكنه يكتب لوحته فقط، والطالب يرى ويكتب لوحته فقط. لا يوجد مفتاح سري في المتصفح.
- لإعداد قاعدة البيانات، شغّل `supabase/boards.sql` في **SQL Editor** (بعد `schema.sql`). الملف آمن لإعادة التنفيذ.

### احتفالات التشجيع أثناء الدرس

- أزرار عائمة ⭐ 🎉 🏮 تظهر للمعلّم في كل الصفحات، وللطالب داخل الدرس فقط، ولكل زر احتفال مختلف: نجوم، أشرطة ملونة، أو فانوس إنجاز.
- تظهر تلقائياً احتفالية عند إنهاء درس جديد، وعند النجاح في اختبار التلاوة، مع وميض نجوم صغير لكل إجابة صحيحة.
- أصوات احتفال خفيفة مولّدة داخل المتصفح (بلا ملفات صوتية خارجية)، مع زر 🔊/🔇 بجانب أزرار التشجيع؛ يُحفظ إعداد الكتم في `localStorage`.
- الاحتفالات بصرية/صوتية فقط ولا تغيّر البيانات؛ وتحترم إعداد «تقليل الحركة» في المتصفح.

### لوحة نجوم الطالب

- من قائمة الطالب «🏆 إنجازاتي» تظهر لوحة نجوم تجمع إنجازاته: درس منجز = ⭐، تلاوة مقبولة = ⭐، واختبار تلاوة ناجح = ⭐.
- تظهر أوسمة متدرجة (بداية، مبتدئ، مجتهد، متألق، فانوس منارة) مع شريط تقدّم إلى الوسم التالي.
- النجوم محسوبة من بيانات Supabase نفسها، فتتحدّث تلقائياً بلا جدول جديد أو حفظ يدوي.
- تظهر النجوم أيضاً في ملف الطالب، وتقارير المعلّم، وتصدير CSV مع خيار ترتيب «الأكثر نجوماً».

### تسجيل تلاوة الطالب ومراجعتها

- في صفحة **القرآن**، يظهر زر 🎙️ بجانب كل آية، وزر **«🎙️ تسجيل السورة كاملة»** أعلى الصفحة للطالب فقط (لا يظهران للمعلّم في وضع المعاينة).
- تسجيل السورة كاملة يُحفظ بـ `scope = 'surah'` و`storage_path = {student_id}/{surah}-full-{timestamp}.webm`، ويُعرض في المراجعة والتقارير بعبارة «السورة كاملة» بدل رقم الآية.
- التسجيل يتم داخل المتصفح عبر `MediaRecorder`، ثم يُرفع إلى Supabase Storage في المسار `{student_id}/{surah}-{ayah}-{timestamp}.webm`.
- يُضاف سجل إلى جدول `recitations` بحالة `pending`، ويظهر للطالب في صفحته الرئيسية عدد التلاوات المقبولة/بانتظار المراجعة، وتظهر حالة الآية بجانبها.
- لم يعد الطالب يختار الدرس يدوياً؛ بدلاً من ذلك تُشتق الدروس المرتبطة من أمثلة `data.js` (مثلاً: التين ٥ ← الغنّة، الإظهار الحلقي، الميم الساكنة، مدّ البدل).
- من صفحة **التلاوات** (للمعلّم فقط) يستمع المعلّم إلى التسجيل عبر رابط موقّع، ثم يضغط **اعتماد** أو **يحتاج إعادة** مع ملاحظة اختيارية. بعد الاعتماد تظهر «بانتظار الاختبار».
- **الاختبار القصير**: للطالب فقط، من الرئيسية (قسم «اختبارات التلاوات») أو زر 📝 بجانب الآية/السورة في صفحة القرآن. سؤال واحد من كل درس محتمل؛ كل إجابة صحيحة تُضاف إلى `completions` عبر RPC آمن + trigger في Supabase، وتظهر فانوس الإنجاز والتقدّم في التقارير. من أخطأ يمكنه إعادة الاختبار.
- التلاوة المعتمدة تُحتسب في التقارير وملف CSV ضمن «تلاوات مقبولة».
- **حذف التلاوة قبل الاعتماد**: للطالب فقط، من الرئيسية (بطاقة «تلاوات بانتظار المراجعة») أو من زر 🗑️ بجانب الآية في صفحة القرآن. يحذف السجل والملف معاً، ويبقى متاحاً حتى لو طلب المعلّم إعادة التسجيل؛ ويختفي فقط بعد الاعتماد.
- الأمان: سياسات RLS تسمح للطالب بالرفع/القراءة داخل مجلده فقط، وتمنعه من تغيير حالة المراجعة أو حذف تلاوة مقبولة؛ والمعلّم وحده يستطيع اعتمادها. نتيجة الاختبار تُرسل عبر `submit_recitation_quiz` (SECURITY DEFINER) التي تتحقق من ملكية التلاوة واعتمادها قبل تسجيل الإنجاز. لا يوجد مفتاح سري في المتصفح.

### تصدير التقارير

في صفحة **التقارير** (للمعلّم فقط):

- **تصدير CSV**: ملف UTF-8 مع BOM ليفتح مباشرة في Excel، ويشمل ملخصاً + جدول تقدّم كل طالب مادةً بمادة.
- **حفظ PDF**: يفتح نافذة الطباعة؛ اختر «Save as PDF» في المتصفح لحفظ التقرير. تم ضبط تنسيق طباعة يخفي القوائم والأزرار ويمنع تقطيع البطاقات.

### إشعارات المهام القريبة الاستحقاق

- عند إسناد مهمة يختار المعلّم **تاريخاً حقيقياً** (`assignments.due_date`)، ويمكنه كتابة نص توضيحي مثل «الخميس». إذا كُتب اسم يوم عربي دون تاريخ، يُحسب أقرب موعد له تلقائياً.
- تظهر الإشعارات في الرئيسية للمعلّم والطالب، وفي صفحة **المهام**، مع شارة 🔔 بعدد المهام القريبة في القائمة الجانبية.
- التذكير يبدأ قبل ٣ أيام؛ وتظهر شارات: `اليوم`، `غداً`، `بعد N أيام`، أو `متأخرة N يوم` بالأحمر.
- لا يُرسل إشعار لمهمة أُنجزت بالكامل، ولا لمهمة بلا موعد.
- يمكن تعديل الموعد لاحقاً من زر **تعديل الموعد** في صفحة المهام، ويُحفظ التغيير في Supabase فوراً.
- المهام التجريبية القديمة («الخميس» و«السبت») تُحوَّل إلى تواريخ فعلية عند تنفيذ `supabase/schema.sql` دون مسح أي تاريخ حددّه المعلّم.

### تنبيهات المتأخرات في تسليم التلاوات

- تُضاف إلى الرئيسية للمعلّم والطالب، وإلى صفحتي **المهام** و**التلاوات** للمعلّم، مع شارة ⏰ في القائمة الجانبية (الرئيسية والمهام للمعلّم، الرئيسية والقرآن للطالب).
- التنبيه يظهر فقط للمهمة التي: (1) لها موعد فعلي مضى، (2) لم يُنجز درسها، و(3) درسها مرتبط بآية يمكن تسجيل تلاوة لها من أمثلة `data.js`. المهام بلا موعد أو بلا تلاوة ممكنة لا تُذكَّر.
- الطالب الذي لم يرسل تلاوة يرى «لم تُسلّم» وعدد الأيام المتأخرة؛ ومن أرسل بعد الموعد يرى «سُلّمت متأخرة N أيام». الحساب مبني على تاريخ أول تسجيل فعلي في `recitations`، لا على تاريخ الاعتماد.
- زر **سجّل التلاوة** يفتح صفحة القرآن عند أول آية مرتبطة بالدرس مباشرةً؛ وزر **عرض الطالب** للمعلّم يفتح لوحة ذلك الطالب.
- انتهاء المهام، أو تعديل موعدها إلى تاريخ لاحق، أو إرسال تلاوة في موعدها يُزيل التنبيه فوراً بعد تحديث البيانات.

### إعادات التلاوات بعد مراجعة المعلّم

- عندما يضغط المعلّم **«يحتاج إعادة»** تُحفظ ملاحظته وتاريخ المراجعة في `recitations`، ويظهر تنبيه **🔁 إعادات مطلوبة بعد المراجعة** للطالب والمعلّم.
- مكان التنبيه: الرئيسية للمعلّم والطالب، صفحة **التلاوات** للمعلّم، وصفحة **القرآن** للطالب، مع شارة 🔁 في القائمة الجانبية.
- يظهر التنبيه ما دام الطالب لم يرسل تلاوة جديدة لنفس الآية/السورة بعد وقت طلب الإعادة؛ ويختفي فور إرسال تسجيل جديد (سواء بانتظار المراجعة أو مقبول).
- زر **🎙️ إعادة التسجيل** لدى الطالب يفتح نافذة التسجيل عند الآية المطلوبة مباشرةً، وزر **عرض الطالب** يفتح ملفه لدى المعلّم.
- يُعرض سبب الإعادة كما كتبه المعلّم، وعدد الأيام منذ طلبها، وعدد الإعادات المطلوبة في إحصاءات الرئيسية وملف الطالب.
- لا يتطلب هذا التنبيه أي تعديل على قاعدة البيانات؛ يستخدم الحقول الموجودة `status` و`teacher_note` و`reviewed_at`.

### تحسينات التقارير وملفات الطلاب

- في صفحة **التقارير**: بحث فوري باسم الطالب، تصفية حسب المستوى، وترتيب حسب الإنجاز/الاسم/الدروس/التلاوات، مع عدّاد للنتائج ورسالة عند عدم وجود مطابقات.
- تصدير CSV يصدر **النتائج المعروضة فقط** بعد البحث والترتيب، ويسجّل في الملف شروط البحث والمستوى وعدد النتائج.
- في صفحة **الطلاب**: زر **ملف** جديد يفتح بطاقة تفصيلية للطالب تشمل تقدّم كل مادة، المهام المسندة وحالاتها، التلاوات وحالات الاختبار، وعدد تأخيرات التلاوات.
- نوافذ الحوار أصبحت قابلة للتمرير بارتفاع أقصى ٨٦٪ من الشاشة، لتعرض الملفات التفصيلية بسهولة على الشاشات الصغيرة.

## 3.1) التقارير الأسبوعية بالبريد (Supabase Edge Function + Resend)

تُرسل رسالة كل **جمعة ٦ مساءً بتوقيت الرياض** (15:00 UTC): ملخّص شامل للمعلّم، ورسالة مخصّصة لكل طالب ببياناته.

### الإعداد لمرة واحدة
1. أنشئ حساباً في [Resend](https://resend.com) وأضف دوميناً مُتحقَّقاً منه للإرسال من https://resend.com/domains.  
   ⚠️ إذا استخدمت `onboarding@resend.dev` دون دومين مُتحقَّق، فستقبل Resend الإرسال **إلى بريد حساب Resend فقط**، وسترفض إرسال تقارير الطلاب إلى عناوين أخرى.
2. في Supabase → **Edge Functions → Secrets** أضف:
   - `RESEND_API_KEY` = مفتاح Resend.
   - `REPORT_FROM_EMAIL` = بريد المرسل المُتحقَّق منه (مثل `منارة@yourdomain.com`).
   - `REPORT_TEST_EMAIL` (اختياري) = بريدك لاستقبال نسخة الاختبار.
   - `REPORT_APP_URL` (اختياري) = رابط التطبيق.
   - `REPORT_CRON_SECRET` = قيمة سرية عشوائية لمنع استدعاء الدالة من غير المجدول.
3. انشر الدالة: `supabase functions deploy weekly-report` (أو الصق الكود من `supabase/functions/weekly-report/index.ts` في لوحة Supabase) مع `verify_jwt = false`.

## 4) ما الذي تحوّل إلى سحابي؟

- `students` ← جدول `students`
- `done` ← جدول `completions`
- `assigns` ← جدول `assignments`
- تسجيلات التلاوة ← جدول `recitations` + Storage bucket `recitations`
- ترقية الطالب ← تحديث `students.level`
- فتح الدرس/الاختبار ← إدراج في `completions`
- إسناد مهمة ← إدراج في `assignments`
- الحالة `mode` / `sid` / `view` تبقى محلية (واجهة فقط)
